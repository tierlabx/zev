> 产品需求文档 — Zev 开源管理后台前端功能补全

## 1. 项目信息

| 项 | 内容 |
|---|------|
| **项目名称** | zev-frontend-enhancement |
| **编程语言/技术栈** | React 19 + TypeScript + Vite + TanStack Router v7 + Zustand(persist) + TanStack React Query + Tailwind CSS + shadcn/ui + Framer Motion + React Hook Form + Zod + Biome |
| **后端依赖** | Go + Gin + GORM + PostgreSQL，已有完整 RBAC API |
| **前端路径** | `F:\03_OpenSource\zev\zev-web\apps\admin\src` |
| **设计规范** | Wolf Steel Design System v2（见 `docs/ui-design-proposal.md`） |

### 原始需求复述

Zev 是一个前后端分离的开源管理后台项目。后端 RBAC API 已完整实现，前端已搭建路由系统、认证、用户 Store、权限 Hook 及基础 CRUD 页面。但存在 8 类功能缺失需要完善：Dashboard 仪表盘、RBAC 按钮级权限补全、表单校验增强、搜索功能接线、错误处理增强、加载状态优化、响应式适配、用户角色分配 UI。本 PRD 旨在明确这些功能的需求范围、优先级与验收标准。

## 4. 需求池

### P0 — 必须实现（核心功能闭环）

#### P0-1: RBAC 按钮级权限控制补全

**现状**：仅用户管理页面有按钮权限控制，角色管理、菜单管理、字典管理页面的所有操作按钮无条件渲染。

**需求**：

| 页面 | 权限标识 | 受控按钮 |
|------|----------|----------|
| 角色管理 | `system:role:create` | "添加角色" 按钮 |
| 角色管理 | `system:role:update` | 行内"编辑"按钮 |
| 角色管理 | `system:role:delete` | 行内"删除"按钮 |
| 角色管理 | `system:role:assign` | 行内"分配菜单"按钮 |
| 菜单管理 | `system:menu:create` | "添加菜单" 按钮 |
| 菜单管理 | `system:menu:update` | 行内"编辑"按钮 |
| 菜单管理 | `system:menu:delete` | 行内"删除"按钮 |
| 字典管理 | `system:dict:create` | "添加类型"/"添加数据"按钮 |
| 字典管理 | `system:dict:update` | 行内"编辑"按钮（类型+数据） |
| 字典管理 | `system:dict:delete` | 行内"删除"按钮（类型+数据） |

**实现方式**：复用现有 `usePermission()` Hook 的 `hasPermission(perm)` 方法，在按钮渲染处添加条件判断，与用户管理页面保持一致的模式。

**验收标准**：
- 无对应权限的用户登录后，相关按钮不可见（DOM 中不渲染，非 disabled）
- 拥有 `*` 通配符权限的超管可看到所有按钮
- 按钮权限判断不影响页面列表数据的正常加载

#### P0-2: 用户角色分配 UI

**现状**：后端已提供 `POST /api/system/user/role/:id` 接口，前端 API 层未定义该函数，用户管理页面无"分配角色"操作入口。

**需求**：
1. 在 `api/system/user.ts` 中新增 `assignUserRole(id: number, roleId: number)` 函数
2. 在用户管理页面操作列新增"分配角色"按钮（权限：`system:user:assign`）
3. 点击后弹出角色分配弹窗，展示角色列表（单选），当前角色预选中
4. 确认后调用 `assignUserRole` 接口，成功后刷新用户列表并 toast 提示

**UI 设计**：
- 弹窗复用现有 Modal 组件，标题"分配角色"
- 角色列表使用 Radio Group 或 Select 组件（与 UserFormDialog 中的角色选择一致）
- 当前用户的 `role_id` 对应角色预选中
- 提交按钮 loading 状态

**验收标准**：
- 点击"分配角色"按钮弹出弹窗，当前角色预选中
- 选择新角色并确认后，用户列表中该用户的角色列实时更新
- 仅拥有 `system:user:assign` 权限的用户可见该按钮

#### P0-3: 搜索功能接线

**现状**：用户管理页面有搜索输入框但 `search` 状态未传给 API（`queryFn` 仅传 `{ page, pageSize }`），且 `UserListParams` 类型无搜索字段。角色管理和字典管理无搜索框。

**需求**：

| 页面 | 搜索字段 | 实现方式 |
|------|----------|----------|
| 用户管理 | 用户名/昵称/邮箱 | 扩展 `UserListParams` 增加 `keyword?: string`，queryFn 传入 search 值 |
| 角色管理 | 角色名称/编码 | 新增搜索框，扩展 `RoleListParams` 增加 `keyword?: string` |
| 字典管理 | 字典名称/类型 | 左侧字典类型面板新增搜索框 |

**防抖搜索**：
- 搜索输入使用 300ms 防抖（`useDeferredValue` 或自定义 debounce Hook）
- 防抖后的值作为 queryKey 的一部分，触发 React Query 重新请求
- 搜索时自动重置页码为第 1 页

**后端兼容**：需确认后端 `/list` 接口是否支持 `keyword` 参数。若不支持，前端先实现前端过滤（仅对当前页数据过滤），并标注为待后端支持的 TODO。

**验收标准**：
- 在搜索框输入关键词后 300ms 自动触发查询
- 搜索结果正确过滤，分页重置到第 1 页
- 清空搜索框恢复显示全部数据

#### P0-4: 表单校验增强

**现状**：所有表单弹窗（UserFormDialog、RoleFormDialog、MenuFormDialog、DictTypeFormDialog、DictDataFormDialog）使用 `useState` + HTML `required` 属性，无字段级校验和错误提示。

**需求**：将所有表单弹窗升级为 React Hook Form + Zod 校验方案。

**校验规则**：

| 表单 | 字段 | 校验规则 |
|------|------|----------|
| 用户表单 | username | 必填，3-20 字符，仅字母数字下划线 |
| 用户表单 | password | 新建时必填，≥6 字符；编辑时可选（留空不修改） |
| 用户表单 | email | 可选，填写时需符合邮箱格式 |
| 用户表单 | nickname | 必填，1-30 字符 |
| 角色表单 | name | 必填，2-30 字符 |
| 角色表单 | code | 必填，2-30 字符，仅字母数字下划线 + 冒号 |
| 菜单表单 | name | 必填，1-30 字符 |
| 菜单表单 | path | 必填（C/M 类型时），合法路径格式 |
| 菜单表单 | permission | 必填（F 类型时），格式 `module:resource:action` |
| 字典类型表单 | name | 必填，2-30 字符 |
| 字典类型表单 | type | 必填，2-50 字符，仅字母数字下划线 |
| 字典数据表单 | label | 必填，1-50 字符 |
| 字典数据表单 | value | 必填，1-50 字符 |

**交互设计**：
- 字段级校验：失焦（onBlur）时触发，错误信息显示在输入框下方，红色文字
- 提交级校验：提交时全量校验，第一个错误字段自动聚焦
- 校验失败时表单整体 shake 动画（参考设计规范 Layer 2 — `x: [0, -5, 5, -5, 0]`）
- 校验通过后按钮进入 loading 状态

**验收标准**：
- 所有表单字段按上述规则进行校验
- 错误提示清晰、位置一致
- 无法提交包含校验错误的数据
- 编辑模式下密码字段留空时不触发必填校验

#### P0-5: 错误处理增强

**现状**：响应拦截器仅处理 401（跳转登录），其他错误通过各 mutation 的 `onError` 单独处理 toast，无统一处理。

**需求**：

在 `api/request.ts` 响应拦截器中增强错误处理：

| 错误类型 | HTTP 状态码/业务码 | 处理方式 |
|----------|---------------------|----------|
| 未授权（Token 过期） | 401 | 清除登录态，跳转 /login（已实现） |
| 权限不足 | 403 | toast.error("权限不足，无法执行此操作") |
| 参数错误 | 400 | toast.error(后端返回的具体错误信息) |
| 资源不存在 | 404 | toast.error("请求的资源不存在") |
| 服务器错误 | 500 | toast.error("服务器异常，请稍后重试") |
| 网络异常 | 无响应（ERR_NETWORK） | toast.error("网络连接异常，请检查网络") |
| 请求超时 | ECONNABORTED | toast.error("请求超时，请重试") |

**实现要点**：
- 在响应拦截器的 `error` 分支统一处理，根据 `error.response?.status` 和 `error.code` 分类提示
- 业务码非 200 的情况已在 `response` 分支处理，保持现有逻辑
- toast 使用已有的 `sonner` 库，确保不重复提示（同一错误只弹一次）
- 401 不弹 toast（直接跳转登录更流畅）

**验收标准**：
- 关闭后端服务后操作，显示"网络连接异常"提示
- 无权限用户尝试受限操作，显示"权限不足"提示
- 后端返回参数错误时，显示具体错误信息
- 401 仍正常跳转登录页，不弹 toast

### P1 — 应该实现（体验提升）

#### P1-1: Dashboard 仪表盘页面

**现状**：仅占位页，显示"仪表盘正在建设中"。

**需求**：实现完整的仪表盘页面，包含 4 个区块：

**区块 1 — 统计卡片（4 张）**

| 卡片 | 数据来源 | 图标 | 趋势 |
|------|----------|------|------|
| 用户总数 | `getUserList` 的 `total` | Users | 本周新增 |
| 角色总数 | `getRoleList` 的 `total` | Shield | — |
| 菜单总数 | `getMenuList` 的 `total` | Menu | — |
| 字典总数 | `getDictTypeList` 的 `total` | BookOpen | — |

- 卡片使用 Framer Motion stagger 入场动画（0.15s 间隔）
- 数字使用 `AnimatedCounter` 组件（`useMotionValue` + `animate()` 从 0 计数到目标值，1.2s）
- 每张卡片底部可选 sparkline 迷你折线图
- 卡片 hover 时 `y: -2px` 微浮动

**区块 2 — 用户活动趋势图**

- 折线图展示近 7 天用户活动趋势
- SVG `pathLength` 从 0 到 1 的绘制动画（0.6s delay 后触发）
- 若后端无活动统计 API，使用模拟数据并标注"示例数据"
- 响应式：移动端占满宽度，桌面端占 2/3 宽度

**区块 3 — 最近活动列表**

- 展示最近 5-8 条系统操作记录
- 每条记录：操作人 + 操作描述 + 时间（相对时间，如"2 分钟前"）
- 列表项 stagger 入场动画（0.05s 间隔）
- 若后端无操作日志 API，使用模拟数据并标注"示例数据"

**区块 4 — 系统健康指标**

- 4 个进度条指标：API 可用率、数据库响应、内存占用、CPU 占用
- 进度条宽度从 0 动画到目标值（0.6s delay，spring 动画）
- 颜色：正常用 `--color-success`，警告用 `--color-accent`，危险用 `--color-error`
- 若后端无健康检查 API，使用模拟数据并标注"示例数据"

**数据获取策略**：
- 使用 React Query 并行请求 4 个 list API（仅取 total 字段）
- queryKey: `["dashboard-stats"]`，staleTime: 60s
- 趋势图/活动列表/健康指标若无对应后端 API，前端使用静态模拟数据，后续后端支持后替换

**验收标准**：
- Dashboard 页面 4 个区块完整渲染
- 统计卡片数字从 0 动画计数到实际值
- 进度条有宽度动画
- 页面加载动画流畅，首屏 < 1.5s
- 空数据状态有合理的占位展示

#### P1-2: 加载状态优化

**现状**：表格加载使用 `isLoading` 传给 ZevTable（内部处理方式待确认），按钮 loading 使用文字"保存中..."，无骨架屏。

**需求**：

| 场景 | 优化方案 |
|------|----------|
| 表格加载 | 替换为骨架屏行（Skeleton），灰色占位条 + shimmer 动画（CSS gradient sweep） |
| 页面切换 | 路由懒加载时显示页面级骨架屏或 Spinner |
| 按钮提交 | loading 时显示 Spinner 图标替换文字（AnimatePresence crossfade），按钮 disabled |
| 卡片/列表加载 | 骨架屏占位 |

**实现要点**：
- 新增 `Skeleton` 组件（若 shadcn/ui 未提供则基于 div + Tailwind animate-pulse 实现）
- 表格骨架屏：根据列数生成对应数量的灰色占位行，行高与实际行一致
- 按钮 loading：左侧 Spinner + 文字 crossfade，参考设计规范 Layer 2

**验收标准**：
- 表格数据加载时显示骨架屏而非空白或 Spinner
- 按钮提交时显示 Spinner 且不可重复点击
- 骨架屏尺寸与实际内容一致，无布局跳动

### P2 — 可以实现（适配增强）

#### P2-1: 响应式适配

**现状**：布局仅有 `sidebarCollapsed` 状态，无移动端 Drawer 适配。字典页面有 `md:grid-cols-3` 基础响应式。

**需求**：

| 场景 | 桌面端 (≥768px) | 移动端 (<768px) |
|------|------------------|------------------|
| 侧边栏 | 固定显示，支持折叠 | 隐藏，汉堡菜单触发 Drawer 抽屉从左滑入 |
| Header | 完整布局（搜索+图标+头像） | 简化（汉堡菜单 + 头像） |
| Tags View | 显示 | 隐藏 |
| 统计卡片 | 4 列横排 | 1 列堆叠（或 2x2） |
| 表格 | 正常显示 | 横向滚动 + 粘性首列 |
| 表单弹窗 | 居中 Modal | 全屏 Sheet（从底部滑入或全屏覆盖） |

**实现要点**：
- 在 `useLayoutStore` 中新增 `isMobile` 状态（通过 `matchMedia` 或 `useMediaQuery` Hook 检测）
- 侧边栏：移动端使用 shadcn/ui `Sheet` 组件包裹，从左侧滑入
- 表单弹窗：移动端切换为全屏模式（`w-full h-full rounded-none`）
- 表格：外层包裹 `overflow-x-auto`，首列添加 `sticky left-0` + 背景色

**验收标准**：
- 在 375px 宽度下页面布局不溢出、不错位
- 汉堡菜单可正常打开/关闭侧边栏抽屉
- 表单弹窗在移动端全屏显示
- 表格可横向滚动，首列粘性

## 5. UI 设计要点

> 遵循 Wolf Steel Design System v2（`docs/ui-design-proposal.md`），以下为各功能模块的设计要点补充。

### 5.1 配色规范

所有新增 UI 必须使用 CSS 变量 token，禁止硬编码颜色值：

| 用途 | Token | 值（Light） |
|------|-------|-------------|
| 页面背景 | `--color-bg-page` | `#F8FAFC` |
| 卡片/表面 | `--color-bg-surface` | `#FFFFFF` |
| 主操作色 | `--color-primary` | `#2563EB` |
| 主文字 | `--color-text-primary` | `#0F172A` |
| 次要文字 | `--color-text-secondary` | `#475569` |
| 成功 | `--color-success` | `#10B981` |
| 错误/危险 | `--color-error` | `#EF4444` |

**注意**：现有代码中存在硬编码颜色（如 `#1677FF`、`#666666`、`text-black`），本次完善过程中应一并替换为 token。

### 5.2 Dashboard 动画序列

页面挂载时的动画编排（参考设计规范 6.3 节）：

```
0.0s  ─ 页面淡入
0.1s  ─ 欢迎标题 fadeUp
0.15s ─ 统计卡片 1 fadeUp
0.20s ─ 统计卡片 2 fadeUp
0.25s ─ 统计卡片 3 fadeUp
0.30s ─ 统计卡片 4 fadeUp（同时数字开始计数动画 1.2s）
0.35s ─ 趋势图卡片 scaleIn（SVG path 开始绘制）
0.40s ─ 活动列表项 stagger 入场（0.05s 间隔）
0.60s ─ 系统健康进度条 width 动画（spring）
```

```
│  ╱╲╱╲╲╱╲  ← Sparkline           │

```

- 卡片：`bg-white rounded-lg border border-slate-200 p-4`，hover 时 `y: -2px`
- 图标容器：`w-10 h-10 rounded-lg`，背景为对应语义色的 light 变体

## 6. 技术约束与依赖

| 约束 | 说明 |
|------|------|
| **后端 API 依赖** | 搜索功能需后端 `/list` 接口支持 `keyword` 参数；Dashboard 趋势图/活动列表/健康指标可能无对应后端 API，前端先用模拟数据 |
| **现有组件复用** | 优先复用 `ZevTable`、`Modal`、`usePermission`、`useConfirm`、`toast(sonner)` 等现有组件和 Hook |
| **React Hook Form + Zod** | 项目已声明依赖，需创建各表单的 Zod schema 并迁移表单状态管理 |
| **Framer Motion** | Dashboard 动画、骨架屏 shimmer、表单 shake 等均使用 Framer Motion 或 CSS animation，需遵循 `prefers-reduced-motion` |
| **Biome 代码规范** | 所有新增代码需通过 Biome lint/format 检查 |
